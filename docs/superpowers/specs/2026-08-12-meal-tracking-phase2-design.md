# 食事記録 Phase 2（統合ビュー・Slackダイジェスト）設計

日付: 2026-08-12
ステータス: 承認済み（実装計画へ）

このドキュメント内のURL例は `weight.example.com` を使う（実環境の設定値はこのリポジトリに書かない。CLAUDE.md参照）。

## 目的

Phase 1で作った食事記録を「体重トラッキング並みに見られる」ようにする。中心は **体重×摂取カロリーの統合ビュー（グラフ）**。加えて日次Slackダイジェストに当日の摂取カロリーを組み込む。

Phase 1の食事タブ（記録専用: メニュー選択・fzfピッカー・日付backfill・PFC表示）はそのまま。今回は「見る」体験を足す。

## 決定事項

- グラフ骨格: **1グラフ2軸重ね合わせ**（体重折れ線=左軸kg、摂取カロリー棒=右軸kcal）
- 配置: **既存の体重グラフ（app.js）を拡張**して統合ビューにする。専用タブや食事タブへのチャート新設はしない
- カロリー表現: **総カロリーの棒（1日1本）**、PFCはツールチップ内訳。PFC積み上げ棒はしない（PFC任意入力で破綻するため）
- **目標設定は入れない**（ユーザー判断で不要と確定）。目標線・残りkcal表示なし
- Slack: 日次ダイジェストに **当日**（ダイジェストのローカル日付）の摂取を1行追加

## 前提（既存構造。Explore調査で確認済み）

- `src/dashboard/app.js`（単一IIFE・約921行）にグローバルな Chart.js line チャートが1つ。6データセット（体重/脂肪量/除脂肪量 × 実測/7日平均）を左軸 `yKg` に載せる
- 期間切替（1m/3m/1y/custom）・実測↔7日平均トグル・表（日次/明細）・テーマ（CSS変数 + `applyThemeToChart`）・密度調整（ResizeObserver）を持つ。すべて再利用する
- 日付軸は `buildDateLabels(from,to)` で全日生成し、`seriesFrom`/`pick` で API の `days`（欠損日なし）を整列、`spanGaps:true` で線を繋ぐ。**この整列機構にカロリーも載せる**
- `GET /api/meals/daily?from&to`（`serveMealsDaily`）は `{ days: [{ d, count, calories, protein_g, fat_g, carbs_g }] }` を返す。**実装済みだが現状UI未使用**。欠損日なし（GROUP BY）
- `getIntakeForDay(env, ymd)`（Phase 1・src/meals.ts）が当日合計を返す。Slackで再利用

## 統合ビュー（app.js）

### データ取得
- `loadData()` の既存 `api/measurements?from&to` 取得に、同じ from/to で `api/meals/daily?from&to` を **並行取得**（Promise.all に追加）
- 取得したカロリー日次を、既存の日付ラベルに整列（`seriesFrom` と同様の date-keyed lookup → `pick('calories')` 等でラベル順配列に。欠損日は null）

### 描画
- 右Y軸 `yKcal`（`position:'right'`, kcal, `beginAtZero:true` 寄り。棒なので0基点が自然）を追加
- 総カロリーの棒データセット（`type:'bar'`, `yAxisID:'yKcal'`, 半透明色, `order` を大きくして折れ線の背面）を1本追加。既存の line データセットは前面
- `applyAxisRanges()` を拡張: 既存の `yKg`（可視line系列から±10%）に加え、`yKcal` を可視カロリーの 0〜max×1.1 でスケール
- ツールチップ: カロリー棒の項目に `P〇 F〇 C〇`（部分合計・未入力は省略、小数第1位）を併記
- `applyThemeToChart()` のハードコード配色配列（現状 line 6本分）にカロリー棒用の色を1つ追加。ダーク/ライト両対応（CSS変数 `--accent-2` 系を流用）
- カロリー棒はカロリーオーバーレイOFF時は非表示、`yKcal` 軸も隠す

### 表示切替（トグル）
- 「カロリーを重ねる」トグルを1個追加（既存の実測/7日平均トグル群の近く）
- **デフォルトON**（統合ビュー）。状態は `localStorage['dash-calorie-overlay']` に保存
- OFF: カロリー棒データセットと `yKcal` 軸を隠し、純粋な体重グラフに戻す

### 表（日次集計）
- 日次テーブル（`renderDailyTable`）に **摂取カロリー列**を1つ追加（既に meals/daily を取得済みなので低コスト）。日付キーで結合、記録なしの日は空欄
- 計測明細（raw）テーブルは対象外

### コード方針
- app.js は既存パターンどおり単一ファイルに追加（無関係な大規模リファクタはしない）。カロリー関連を1つの論理セクションにまとめ、データセット index 定数・軸・テーマ配列を拡張する形で既存6系列を壊さない

## Slackダイジェスト（src/slack.ts / digest系）

- 既存の日次ダイジェスト送信時に、当日（ダイジェストのローカル日付 ymd）の摂取を `getIntakeForDay(env, ymd)` で取得
- 体重情報の並びに1行追加: `摂取: 1850 kcal (P90 F55 C210)`
  - 記録0件の日はこの行を**省略**（ノイズを減らす）
  - PFCは入力済み分の部分合計（既存仕様）。PFCが全て未入力ならカロリーのみ `摂取: 1850 kcal`
  - 小数は整数丸め（kcal）/小数第1位（PFC g）
- mrkdwn制約: 全角括弧直後のバッククォートは認識されないため、コードスパンの前後は半角括弧+空白にする（既存Slackフォーマットの制約に従う）

## エラー処理

- カロリー日次の取得失敗時: カロリーオーバーレイなしで体重グラフを描画（統合ビューの取得失敗が体重表示を壊さない）。コンソールにエラー
- Slack: `getIntakeForDay` 失敗時は摂取行を省いてダイジェストを送る（ダイジェスト自体は落とさない）

## テスト

- データ層（`getDailyIntake` / `getIntakeForDay`）は Phase 1 でテスト済み。再利用のみ
- app.js の描画はブラウザ依存で単体テスト対象外。配信・HTML要素（カロリートグル・canvas）の存在は既存 dashboard 配信テストに準じて確認。`ASSET_VERSION` 更新
- Slackダイジェスト: 当日摂取ありの整形 / 記録0件時の行省略 / PFC一部欠損時の整形 を digest テストに追加。日付seedは固定時刻 `${ymd}T03:00:00Z`
- 回帰: 既存の体重グラフ表示・体重系のテストが壊れていないこと（typecheck + vitest 全通過）

## スコープ外（Phase 2）

目標設定・目標線・残りkcal表示、あすけん的スコア/アドバイス（Phase 3）、自然文AI栄養推定、食品DB・バーコード、体重目標線、計測明細テーブルへのカロリー付与、体重×カロリーの相関係数など統計指標。

## リスク・前提

- app.js の2軸拡張は既存の体重グラフ描画に回帰を出しうる。既存の体重表示（期間切替・実測/平均・表・テーマ・密度）が壊れていないことを実データで目視確認する
- Slackの当日摂取は送信時刻までの記録合計。正確な当日合計には `digest_time` を1日の終わり（遅め）に設定しておくことが前提（仕様として明記）
- 2軸グラフはスケールの取り方で印象が変わる。右軸レンジ（0基点/上限係数）は実データで最終調整する
- app.js は約921行と既に大きい。今回の追加でさらに増える。大規模リファクタはスコープ外だが、カロリー処理は独立セクションに閉じて見通しを保つ
