# 消費カロリーへの基礎代謝（BMR）組み込み 設計

日付: 2026-08-13
ステータス: 承認済み（方式選択済み）

このドキュメント内のURL例は `weight.example.com` を使う（実環境の設定値はこのリポジトリに書かない。CLAUDE.md参照）。

## 目的

「消費」を運動の有無によらず毎日成立させる。運動記録の消費kcalに加えて、**基礎代謝（BMR）を実測の除脂肪体重から日次で推定**し、摂取と同じ土俵で見せる。

## 決定事項

- **算定式は Katch-McArdle**: `BMR = 370 + 21.6 × 除脂肪体重(kg)`
  - 理由: このアプリは除脂肪体重の**実測**を持っており、それを直接使える唯一の式。身長・年齢・性別の設定が一切不要（Withingsからの身長取得も不要になる）
- **その日のFFM** = その日以前で最も新しい計測の `fat_free_mass`（carry-forward。運動の体重スナップショットと同じ規則）。実測が一度も無い期間は `bmr = null`
- **保存しない**（読み取り時算出）。計測が後から入れば過去日のBMRも自動で正しくなる。スキーマ変更なし
- **正直さのラベル**: BMRは推定であり、日常活動・食事誘発熱産生は含まない。消費の内訳（基礎/運動）を常に見せ、「推定」であることをAPI説明・UIツールチップに明記する

## API変更（/api/exercise/daily）

- 期間内の**全日**を返すようになる（従来は運動記録がある日のみ）
- `DailyExercise` に `bmr: number | null` を追加。運動が無い日は `calories_burned`/`strength_volume` は null、counts は 0
- 総消費はクライアント側で `bmr + (calories_burned ?? 0)`（bmrがnullなら運動分のみ）

## ダッシュボード（体重グラフ）

- 消費棒（紫）= 基礎代謝＋運動消費の合計。ツールチップに内訳（`基礎 1750 + 運動 294`）
- ネット線 = 摂取 − 総消費（摂取がある日のみ）。**負値（赤字）を許容**し、kcal右軸は負値まで拡張
- 日次テーブルの消費/ネット列も同じ定義に

## Slackダイジェスト

- `*消費* : 2044 kcal (基礎 1750 + 運動 294)` — bmrがあれば毎日出す（運動なしの日は `(基礎代謝)` のみ）
- `*ネット* : -392 kcal (摂取−消費)` — 摂取と消費の両方がある日のみ

## やらないこと

- TDEE（活動係数）・食事誘発熱産生の推定（当て推量が強すぎる）
- Withingsからの身長取得（Katch-McArdleでは不要）
- BMRのDB保存・スナップショット
